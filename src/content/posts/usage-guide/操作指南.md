# GIT拉取操作指南

---

## 一、新电脑拉取项目

### 1. 环境准备

在开始之前，确保新电脑已安装以下软件：

| 软件 | 最低版本 | 下载地址 |
|------|---------|---------|
| Node.js | ≥ 22 | https://nodejs.org/ |
| Git | 最新版 | https://git-scm.com/ |

安装 pnpm（项目强制使用 pnpm，不允许使用 npm/yarn）：

```bash
npm install -g pnpm
```

> 验证安装：`node -v`、`pnpm -v`、`git --version`

---

### 2. 克隆仓库

```bash
# 进入你想存放项目的目录
cd D:\网站

# 克隆仓库
git clone https://github.com/shifulong7/firefly.git

# 进入项目目录
cd firefly
```

> 如果使用自己的 Fork 仓库，请将上方地址替换为你自己的仓库地址。

---

### 3. 安装依赖

```bash
pnpm install
```

安装完成后，`node_modules/` 目录会自动生成。

---

### 4. 验证安装

启动本地开发服务器：

```bash
pnpm dev
```

浏览器访问 `http://localhost:4321/firefly/` 看到博客页面即表示成功。

---

## 二、已拉取电脑的更新操作

当你已经在本地有一份项目副本，需要从远程仓库拉取最新代码时：

### 1. 拉取最新代码

```bash
# 进入项目目录
cd D:\网站\新模板\firefly

# 拉取远程最新代码
git pull origin main
```

> 如果你使用的是其他分支，将 `main` 替换为对应分支名。

---

### 2. 更新依赖

如果 `package.json` 有变化（新增了依赖或版本更新），需要重新安装：

```bash
pnpm install
```

> 如果 `package.json` 没有变化，可以跳过此步骤。

---

### 3. 清理缓存（可选）

如果遇到构建异常或页面显示不正常，可以清理缓存后重新安装：

```bash
# 删除 node_modules 和 Astro 缓存
rm -rf node_modules .astro dist

# 重新安装依赖
pnpm install
```

Windows PowerShell 版本：

```powershell
Remove-Item -Recurse -Force node_modules, .astro, dist
pnpm install
```

## 三、项目更新到网站（部署）

本项目支持多种部署方式，以下分别介绍。

### 方式 A：GitHub Pages 部署

项目已配置为部署到 GitHub Pages，站点地址为 `https://shifulong7.github.io/firefly`。

#### 手动构建并部署

```bash
# 1. 构建生产版本
pnpm build

# 2. 构建产物在 dist/ 目录
# 将 dist/ 目录的内容推送到 gh-pages 分支即可
```

#### 使用 GitHub Actions 自动部署（推荐）

在仓库中创建 `.github/workflows/deploy.yml`，配置自动构建和部署到 GitHub Pages，推送代码后自动触发。

---

### 方式 B：Vercel 部署

项目包含 `vercel.json` 配置文件，支持一键部署到 Vercel。

#### 首次部署

1. 访问 https://vercel.com/new，导入 GitHub 仓库
2. Vercel 会自动识别 `vercel.json` 中的配置：
   - 框架：`astro`
   - 构建命令：`pnpm build`
   - 输出目录：`dist`
   - 安装命令：`pnpm install`
3. 点击 Deploy 即可

#### 后续更新

推送代码到 GitHub 后，Vercel 会自动触发重新部署，无需手动操作。

---

### 方式 C：Cloudflare Pages 部署

项目包含 `wrangler.jsonc` 配置，支持部署到 Cloudflare Pages。

```bash
# 1. 构建
pnpm build

# 2. 部署到 Cloudflare Pages
npx wrangler pages deploy dist
```

---

### 部署前注意事项

- **修改站点 URL**：部署前确认 `src/config/siteConfig.ts` 中的 `site_url` 与实际部署地址一致
- **修改 base 路径**：确认 `astro.config.mjs` 中的 `siteBase` 配置正确（当前为 `/firefly/`）
- **构建时间**：完整构建包含 LQIP 生成、字体子集化、Pagefind 索引等步骤，首次构建可能需要较长时间

## 四、本地运行与测试命令

### 常用命令一览

| 命令 | 说明 |
|------|------|
| `pnpm dev` | 启动本地开发服务器（默认 `localhost:4321`） |
| `pnpm build` | 构建生产版本到 `dist/` 目录 |
| `pnpm preview` | 本地预览已构建的网站 |
| `pnpm check` | 检查代码中的类型错误 |
| `pnpm format` | 使用 Biome 格式化代码 |
| `pnpm lint` | 使用 Biome 检查并自动修复代码 |
| `pnpm type-check` | TypeScript 类型检查（不输出文件） |

---

### 内容创作命令

| 命令 | 说明 |
|------|------|
| `pnpm new-post <文件名>` | 创建一篇新文章 |
| `pnpm new-d <内容>` | 创建一条动态（简短写法） |
| `pnpm new-dynamic <内容>` | 创建一条动态（完整写法） |

示例：

```bash
# 创建新文章
pnpm new-post my-first-post

# 创建一条动态
pnpm new-d 今天天气真好
```

---

### 其他工具命令

| 命令 | 说明 |
|------|------|
| `pnpm lqips` | 单独生成图片低质量占位符 |
| `pnpm astro --help` | 查看 Astro CLI 帮助 |

---

### 典型开发流程

```bash
# 1. 启动开发服务器
pnpm dev

# 2. 编辑文章/代码（浏览器自动热更新）

# 3. 开发完成后，检查代码
pnpm lint
pnpm check

# 4. 构建生产版本
pnpm build

# 5. 本地预览确认无误
pnpm preview

# 6. 提交并推送
git add .
git commit -m "更新内容描述"
git push origin main
```

## 附录：项目配置文件说明

主要配置文件位于 `src/config/` 目录：

| 文件 | 说明 |
|------|------|
| `siteConfig.ts` | 站点基础配置（标题、URL、主题色、页面开关等） |
| `navBarConfig.ts` | 导航栏链接配置 |
| `sidebarConfig.ts` | 侧边栏组件配置 |
| `profileConfig.ts` | 个人资料配置（头像、名字、社交链接） |
| `footerConfig.ts` | 页脚配置 |
| `backgroundWallpaper.ts` | 壁纸/背景配置 |
| `commentConfig.ts` | 评论系统配置 |
| `analyticsConfig.ts` | 统计分析配置 |
| `friendsConfig.ts` | 友链配置 |
| `musicConfig.ts` | 音乐播放器配置 |
| `fontConfig.ts` | 字体配置 |
| `effectsConfig.ts` | 动画特效配置（樱花等） |
